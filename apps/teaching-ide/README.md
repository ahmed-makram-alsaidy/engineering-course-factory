# @course-factory/teaching-ide (P4 foundation, P5.12 passive terminal UI)

The **Teaching IDE** — the first user-visible runtime application in Course Factory: an Electron desktop shell that will eventually be used to record programming demonstrations.

## Responsibility (P4 foundation + P5.12 passive terminal UI)

**The IDE renders and navigates; the terminal is a passive runtime surface.**

- loads a compiled lesson IR (canonical P3 contract) **as data** and inspects it
- renders a recording-friendly layout: file explorer, Monaco editor, passive terminal, sandboxed result preview, lesson context, dev IR inspector
- provides a non-executing playhead (previous/next beat) that highlights and describes the current step — navigation alone never executes
 - P5.12 passive terminal: Run / Stop / Cancel / Reset / Clear over the five identifier-only IPC methods plus preload-local `onEvent`; trusted command/cwd metadata with a live result badge; real output from structured runtime events in the existing xterm surface (stdin stays disabled, no input forwarding); subscribe-before-snapshot replay with per-process transcripts; record-safe `/workspace` labels and UI-safe errors
 - P5.13 full verification: the complete P5.1–P5.12 tree re-verified with zero IDE/engine change (every Testing-Plan row green in real Docker, 0 skipped; production build + bundle markers + `--smoke` navigation-inert green)
  - P5.14 visual smoke: `--smoke-terminal` drives the main-authorized safe fixture (`smoke-terminal.json`, single-foreground P5_OK) through production IPC/Docker with correlated main/renderer/PNG evidence (true exit 0, PASS badge, xterm write-callback seq match, 1600x900 + 1280x720 + record-safe screenshots, container teardown); ordinary `--smoke` stays navigation-only
  - P5.15 gate/review: the authoritative final gate (`scripts/validate-p5.mjs`) is green end to end (153 checks, 649 tests, every per-phase REAL Docker integration, three correlated visual smokes with PNG evidence, security/boundary audits, 0 owned containers; one authorized close-lifecycle repair with regression tests) — P5 Real Terminal Engine is COMPLETE; P6 Typing Engine NOT started

It must **never**: accept command/cwd/env/image/mount/shell text from the renderer, spawn shells/PTYs, open or navigate URLs, auto-type code (`type_code` belongs to P6), apply replacements, record video, or gain Node access in the renderer. P5 owns real terminal execution, P6 typing playback, P7 browser automation, P9 recording.

## Development command

```bash
# from the repository root
npm run dev:teaching-ide        # build (esbuild main + vite renderer) and launch
npm run build:teaching-ide      # build only (dist/, git-ignored)
npm run test:teaching-ide       # node --test model/IR/safety suites
npm run smoke:teaching-ide      # app package: build + machine-readable smoke launch
# from apps/teaching-ide (requires Docker + CF_TERMINAL_RUNTIME_IMAGE + config/paths.json):
npm run smoke:terminal          # P5.14 visual smoke (real Docker + xterm + PNG evidence)
```

The app launches at 1600×900 (minimum 1280×720). `--window-size=1280x720` is accepted for validation.

## Architecture

```
apps/teaching-ide/
  electron/main.ts        # window lifecycle, IPC (3 P4 handlers + 5 identifier-only terminal channels), fixture loading + IR validation, --smoke
  electron/preload.ts     # contextBridge: getMeta / loadLesson / reportReady + terminal (5 methods + preload-local onEvent) — nothing else
  electron/terminal-host.ts + execution-catalog.ts  # P5.11 Safe IPC wiring (sender validation, owner binding, reviewed catalog, shutdown barrier)
  src/model/              # pure, testable state: workspace tree, editor tabs, playhead,
                           #   operation descriptors, safe mode, IR adapter types,
                           #   terminal-runtime.ts (P5.12 passive view: trusted events only)
  src/model/ir-loader.ts  # Node-side validation via @course-factory/lesson-compiler/ir
  src/ui/                 # React components + design tokens (CSS variables); TerminalPane is the P5.12 passive surface
  src/fixtures/           # bundled synthetic workspace (Vite ?raw) — demo-node-app
  fixtures/compiled-lessons/  # compiled IR demos generated by the canonical P3 compiler
  tests/                  # node --test suites (model, ir, safety, terminal-ipc, terminal-runtime + real-Docker passive-UI)
```

## Security boundary

- `contextIsolation: true`, `nodeIntegration: false`, `sandbox: true`
- The renderer has **no** Node access; `window.cfApi` (preload bridge) exposes exactly the three P4 functions plus `terminal` (five identifier-only methods + preload-local `onEvent`). No fs / child_process / shell / process / Docker / PTY / generic IPC reaches the renderer. Enforced by static tests (`tests/safety.test.ts`, `tests/terminal-runtime.test.ts`).
- Strict CSP in `index.html`; Monaco and xterm bundle locally (no CDN, fully offline).

## P4 limitations (P5.12 update)

- The terminal is a **passive runtime surface** (xterm with `disableStdin`, no input forwarding; Run/Stop/Cancel/Reset/Clear send identifiers only; real output arrives as structured events with a live result badge; Clear is display-only).
- The result panel shows a **static sandboxed fixture preview**; authored URLs appear as metadata only.
- Editor content changes only through explicit user typing; tabs/buffers are in-memory.
- The file explorer shows the bundled synthetic workspace only; it never browses user directories.
